# Fleet Command scenario converter

`scs_converter.py` is a dependency-free Python CLI that parses Fleet Command
`.scs` scenario files and emits structured JSON. It handles quoted fields,
multiline text blocks, entities, groups, alliances, goals, waypoints and
random movement boxes. The bitmap/palette tail is intentionally skipped.

See [SCS_FORMAT.md](SCS_FORMAT.md) for the detailed format reference.

```sh
python3 scs_converter.py Single04.scs -o Single04.json
```

The JSON separates `aircraft`, `land_units`, `vessels`, `air_stations`,
`air_corridors`, `formations`, `groups`, and `triggers_goals`. Header values with one value are emitted as
scalars (for example, `metadata.month`); only genuinely multi-value fields such
as `metadata.latlong` remain arrays. Empty attributes are emitted as JSON
`null`.

## Map symbols

The browser map uses SVG symbols generated by the [`military-symbol`](https://pypi.org/project/military-symbol/) package, installed here as a `uv` tool. The generated files are checked into `assets/symbols/` so the static website does not need Python at runtime. To regenerate them after changing the symbol catalogue:

```sh
python3 generate_symbols.py
```

If the executable is not on `PATH`, pass its uv-tool path explicitly with
`--binary /path/to/military-symbol`. The generator creates friendly, hostile,
and neutral variants for aircraft, surface vessels, submarines (including
SSBN, SSGN, SSN, and SSK), land units, SAMs, artillery, and air stations.

## Sea Power mission generation

`seapower_generator.py` converts the custom Fleet Command JSON into a best-effort
Sea Power mission INI. It uses the unit definitions under
`SeaPower_StreamingAssets/{aircraft,vessels,land_units}` and the editable
`seapower_mapping.json` file. Explicit mappings are tried first, followed by
class/country-aware matching and conservative generic fallbacks. Every fallback,
ambiguous match, unsupported partial-damage goal, and non-portable attachment is
reported on stderr.

```sh
python3 seapower_generator.py Single04.json Single04_seapower.ini \
  --streaming-assets SeaPower_StreamingAssets \
  --mapping seapower_mapping.json
```

Fleet Command geographic positions are converted to Sea Power's local
`RelativePositionInNM=x,altitude,z` coordinates around `metadata.latlong`.
Friendly, enemy, and neutral objects become Taskforce 1, Taskforce 2, and
Neutral sections. Routes and destruction goals are carried over where Sea Power
has a corresponding representation; partial-damage goals use a destruction
workaround and are warned about.

Fleet Command probability groups are converted to editor-safe runtime candidates.
When an always-present group contains multiple unrouted members with partial
probabilities (for example the pirate scenario's USN DD/FF group), each candidate
gets its own valid Sea Power unit section with `SpawnChance=1/N`. This avoids the
Sea Power editor interpreting a comma-separated `Type` list as a literal filename;
the result approximates the source's one-random-member behavior at runtime.

Airbases are emitted with `CustomAirGroup=True`. Their Fleet Command aircraft
attachments are aggregated into entries such as `usn_p-3c=Default,4`; bases with
no assigned aircraft receive an empty custom air group, preventing Sea Power's
built-in default squadrons from appearing and acting autonomously.

Fleet Command air corridors are represented as neutral civilian aircraft
traffic. Each corridor becomes a `civ_707` or `civ_c340` aircraft route with
the corridor endpoints, midpoint altitude, heading, speed, and requested
quantity preserved as closely as Sea Power's mission format allows.

The generator also accepts a directory and converts all `.scs`, `.sct`, `.scm`,
and `.scc` scenarios in one pass:

```sh
python3 seapower_generator.py FleetCommand_scenarios \
  --output-dir SeaPower_Missions_Generated \
  --year 1985
```

The batch run writes `conversion_warnings.txt` and `quality_report.json` next to
the generated missions. The report records mapped units, omitted units,
unsupported features, and warning categories for each scenario.

Vessel `AIRCRAFT` attachments are expanded into records containing `name`,
`variant`, `class`, `country`, `quantity`, and named `alert_status` entries.
Alliance declarations expose `member_count` and `alliance_ids`; group
declarations expose named identifiers such as `group_id`, `alliance_id`,
`formation_id`, and `parent_group_id`.

Alliance numbers are scenario-local IDs rather than country codes. The JSON
also includes an `alliances` table and resolved `alliance_role`,
`alliance_country`, and `alliance_countries` fields on units, inferred from
the alliance declarations, explicit `COUNTRY` values, tasking text, and the
historical coalition context represented by the scenario. Coalition alliances
can contain multiple countries, so their singular country field is `null`.

The SCS grid has no documented projection in the supplied format. The default
conversion is a local equirectangular approximation using the scenario
`LATLONG`, a 10-degree map-grid center of `(555600, 555600)`, and `111120`
units per degree. These defaults are supported by the repeated `0` to
`1111200` corridor-grid values in the supplied scenarios. Override them when a
different map reference is known:

```sh
python3 scs_converter.py scenario.scs --origin-x 0 --origin-y 0 \
  --units-per-degree 100000
```
